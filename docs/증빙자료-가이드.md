# 증빙 자료 준비 가이드

제출 패키지의 **증빙 자료 2종**을 만드는 방법입니다.
스크린샷은 반드시 **배포된 URL(`https://....vercel.app`)** 에서 촬영해야 합니다.
(주소창이 함께 보이도록 찍으면 "실제로 배포되어 동작한다"는 증거가 됩니다.)

파일은 `docs/screenshots/` 폴더에 아래 이름으로 저장하세요.

---

## 1. 서비스 스크린샷 (1세트 = 최소 4장)

| 파일명 | 내용 | 촬영 방법 |
| --- | --- | --- |
| `01-desktop-home.png` | 데스크톱 전체 화면 (홈 + 메뉴) | 브라우저 최대화 후 `Win + Shift + S` |
| `02-mobile-home.png` | 모바일 화면 | 아래 "모바일 화면 만드는 법" 참고 |
| `03-ai-input.png` | AI 기능에 값을 입력한 상태 | 폼을 채우고 버튼을 누르기 직전 |
| `04-ai-result.png` | **AI 결과가 표시된 화면** | 타임테이블이 보이는 상태 |
| `05-ai-error.png` | 실패 처리 안내 화면 | 할 일을 비우고 제출 |
| `06-mobile-ai-result.png` | 모바일에서 AI 결과 | (권장) 반응형 증빙 강화 |
| `07-dark-mode.png` | 다크 모드 화면 | (선택) 보너스 항목 증빙 |

### 모바일 화면 만드는 법 (실제 휴대폰이 없어도 됩니다)

1. 배포 URL을 크롬에서 엽니다.
2. `F12` → 왼쪽 위의 **기기 아이콘**(`Ctrl + Shift + M`) 클릭
3. 상단에서 **iPhone 14 Pro** 또는 **Pixel 7** 선택
4. `Ctrl + Shift + P` → `screenshot` 입력 → **Capture screenshot** 선택
   (전체 페이지가 필요하면 **Capture full size screenshot**)

### 촬영 시 주의

- **주소창에 배포 URL이 보이게** 찍습니다.
- 다른 탭의 제목, 북마크, 개인 파일명이 함께 찍히지 않게 합니다.
- 개발자 도구의 Network 탭을 함께 찍는다면, **요청 헤더에 키가 없다는 점**을 보이는 것은 좋지만
  응답 본문이나 환경 변수 화면은 찍지 마세요.
- **Vercel의 Environment Variables 화면은 절대 캡처하지 마세요.** (키 노출)

## 2. AI 코딩 도구 사용 증빙 (1세트)

과제에서 요구하는 "AI 코딩 도구 사용 과정" 증빙입니다. 두 가지를 함께 제출하면 충분합니다.

### (a) 작업 기록 문서

[`AI-코딩도구-사용기록.md`](AI-코딩도구-사용기록.md) 에 실제 진행 순서, 지시한 내용,
발견한 문제와 수정 과정이 정리되어 있습니다. 이 파일을 그대로 제출하면 됩니다.

### (b) 대화 로그 스크린샷

| 파일명 | 내용 |
| --- | --- |
| `ai-log-01-요구사항.png` | 어떤 서비스를 만들지 지시한 대화 |
| `ai-log-02-구현.png` | 코드를 생성/수정하는 과정 |
| `ai-log-03-오류수정.png` | **문제를 발견하고 원인을 파악해 고친 대화** (가장 중요) |

> 평가에서 중요한 것은 "코드를 받았다"가 아니라 **"문제를 발견하고 원인을 설명하며 고쳤다"** 입니다.
> 이 프로젝트에서 실제로 있었던 수정 사례는 `AI-코딩도구-사용기록.md` 의 4번 항목을 참고하세요.

**스크린샷을 찍기 전에 확인**: 대화 창에 API 키가 적혀 있지 않은지 반드시 확인하세요.

## 3. 최종 제출 체크리스트

### 필수 5종

- [ ] **배포된 웹 서비스 URL** — 동료가 접속해 AI 기능까지 테스트 가능한 상태
- [ ] **GitHub 저장소 URL** — 프론트(`css/`,`js/`,`index.html`)와 백엔드(`api/`)가 구분되어 있고 커밋 이력이 있음
- [ ] **README.md** — 서비스 소개 / 기술 스택 / 실행·배포 방법 / **배포 URL** / **환경 변수 설정 방법**
- [ ] **서비스 기획서** — `docs/서비스기획서.md` (목적·타겟·페이지 구성·핵심 기능·AI 입출력·실패 처리 기준)
- [ ] **증빙 자료** — 스크린샷 세트 + AI 코딩 도구 사용 기록

### 제출 직전 최종 점검

- [ ] `README.md` 상단의 `__배포후_여기에_URL을_적어주세요__` 를 실제 주소로 교체했는가?
- [ ] `docs/서비스기획서.md` 의 배포 URL도 교체했는가?
- [ ] `.env` 파일이 GitHub에 올라가지 **않았는가**? (저장소 페이지에서 파일 목록 확인)
- [ ] 커밋 이력에 키 값이 들어간 파일이 없는가?
- [ ] 스크린샷·문서 어디에도 실제 키 문자열이 없는가?
- [ ] 배포 URL을 **시크릿 창**으로 열어 처음 방문자 기준으로도 정상 동작하는가?
- [ ] 휴대폰으로 실제 접속해 확인했는가?

### 키가 노출된 것을 발견했다면

1. **먼저 키를 폐기(revoke)하고 재발급합니다.** (파일을 지우는 것보다 이게 우선입니다)
2. Vercel 환경 변수를 새 키로 바꾸고 재배포합니다.
3. 저장소에서 해당 파일을 제거하고 커밋합니다.
   ```bash
   git rm --cached .env
   git commit -m "chore: 환경 변수 파일 추적 제외"
   git push
   ```
